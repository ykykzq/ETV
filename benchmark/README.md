# ETV benchmark pairs

This directory stores test-specialized TTIR pairs captured from the ntops pytest suite.

Each case uses the following layout:

```text
benchmark/<operator>/<stable-test-id>/
  manifest.json
  lhs/
    launch-000.ttir
    ninetoothed-source/
  rhs/
    reference-000-000/
      fx-graph.txt
      fx-code.py
      capture.json
      selected-000.ttir
      inductor-source/
  pairspec/
    pair.json
    status.json
  results/
    pytest.xml
    pytest.log
    formal/
```

`manifest.json` records the full pytest node ID, parameter specialization, exact
ninetoothed launch selected by Triton's runtime autotuner, original reference
expression and runtime inputs, FX graph, TorchInductor artifacts, and all failures.
Cases that are skipped, fail before TTIR generation, compile to no Triton kernel, or
cannot be represented by the current PairSpec schema remain in the benchmark with an
explicit status instead of being omitted.

Collection deliberately runs each pytest node in its own process and cache namespace.
`tools/collect_ntops_benchmark.py` creates or resumes the cases. The PairSpecs are
generated by the conservative mappings authored in
`tools/generate_benchmark_pairspecs.py`; the script only emits a spec when both sides
have one actually selected TTIR launch, one output tensor, and one traceable `tt.store`.
`tools/run_benchmark_verification.py` runs ETV for every emitted PairSpec and records
all `PROVED`, `DISPROVED`, `UNKNOWN`, and not-run results.

The complete result is in [`REPORT.md`](REPORT.md), with the same data available in
`summary.json`. The raw aggregate files are `collection-summary.json`,
`pairspec-summary.json`, and `formal-summary.json`.

The end-to-end workflow is:

```bash
.venv-nt025/bin/python tools/collect_ntops_benchmark.py \
  --jobs 8 --gpus 0,1,2,3,4,5,6,7
.venv-etv/bin/python tools/generate_benchmark_pairspecs.py
.venv-etv/bin/python tools/run_benchmark_verification.py --jobs 8 --timeout 60
.venv-etv/bin/python tools/summarize_benchmark.py
```

GPU collection must run in an environment where `torch.cuda.is_available()` is true.
The collector is resumable, and `--rerun` can refresh a selected `--operator` or
`--node` without deleting other cases.
